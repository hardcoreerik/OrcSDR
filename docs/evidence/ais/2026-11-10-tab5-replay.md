# AIS on the Tab5: replay evidence, 2026-11-10

Device: M5Stack Tab5 development unit on COM17 (identity checked by the pairing key and boot logs, not by the port number). Firmware: branch `claude/ais-integration-hardware-79f921`, app image 5,585,680 bytes, SHA-256 `2D46AD15CE62700882E51B5AEC9845AC0883E3786F8E3F3602C765ADFF484B75`, ESP-IDF 5.5.4, esp_rtl_sdr v0.9.6 pin unchanged. App partition only was flashed; NVS, bootloader and C6 firmware untouched.

**Level of evidence:** synthetic IQ replayed over a private rtl_tcp substitute server on the lab LAN. This proves the decode, state and display path on the device. It does **not** prove reception sensitivity, behaviour with real RF, or sustained USB reception. Nothing was transmitted over the air. The lab receiver saw only noise.

## Test signal

`tools/ais_make_iq.py` (written from ITU-R M.1371-5 Annex 8 and Annex 2, no code shared with the OrcSDR receiver), 60 s, 240 kS/s CU8 centred on 162.000 MHz, noise sigma 0.01, seed 162, MID 100 identities (unallocated). 43 transmissions: Types 1 x10, 2 x6, 3 x6, 4 x6, 5 x3, 18 x4, 21 x4, 24 x4, alternating between both channels, per-station carrier offsets up to 400 Hz, amplitude 0.18 to 0.42.

Oracles, independent of each other: (1) the generator's own payload bytes and field values; (2) the pyais 2.9.4 decode of the generator's NMEA sentences (208 fields compared, pass); (3) the OrcSDR host decoder on the same IQ file.

| Main task stack high-water | 4,312 bytes free of 16,384 | after the soak; map page included |

| Static D/IRAM | 370,316 B used, 75,076 B remain | one build only; no controlled before/after, so no AIS delta is claimed |

Observation, not attributed: during the soak (Wi-Fi rtl_tcp stream active) `dma_min` fell to 15,571 B, lower than the 18.5 KB seen in earlier rtl_tcp sessions. Other work running at the same time (USB source tests, many reconnects) was not separated out, so this may be unrelated to AIS. Needs a repeat with only AIS open.

## Defects found on the device and fixed
- Opening AIS overflowed the main task stack (17 KB `Snapshot` temporary): found by flashing, fixed by building it in place; the status serial reply buffer moved to PSRAM.
- Receiver failed above about 1.5 kHz carrier offset (host stress test); fixed with a per-burst tracker.
- Messages and Protocol list rows ran under the UP/DOWN buttons; fixed.
