# Database format — v0.1 design contract (wire layout review gate)
Country-independent normalized entities: authority/source record, license, authorization, site/antenna, emission, coverage geometry, party (licensee), links. Stable IDs scoped by country + authority + source system + source key, never callsign alone. Frequency Hz unsigned 64-bit inclusive low/high; exact point low=high; preserve allocation vs transmit vs receive roles, frequency blocks and original units/precision. Do not invent center frequency or transmitter. WGS84 signed E7 latitude/longitude with explicit presence and accuracy/source; missing is not zero. Geometry types point, bounded polygon/multipolygon, nationwide, other geographic area, unknown; distinguish licensed area from propagation. Preserve multiple sites, antennas, emissions and assignments, station class, status, effective dates, source publication date, provenance and unknowns. Broadcast, microwave, satellite/earth, mobile, nationwide, area and individually licensed authorizations supported; mailing address never a site.
Explicit little-endian versioned serialization, no native struct dumps. Research proposes fixed header magic/version/header length/package identity/section table with checked uint64 offset+length and record counts/stride; deterministic sorted indices for exact/range interval overlap (must find long spanning blocks), callsign, license ID, normalized organization, service/emission/status and geographic candidates. Sparse/paged indices and bounded reads; UTF-8 length-prefixed string table with max decoded length, checked offset/length, no implicit NUL trust. Specify missing vs empty and normalization (original retained), stable ordering, pagination, invalid ranges and antimeridian/polar semantics. Explicit source coverage table incl unsupported feeds and records with no site. Format proposal must specify every field width, offset, index node structure, bounds, unknown extension rules and golden vectors before freeze. Major mismatch reject; minor/optional sections only when explicitly compatible. No unbounded allocation or memory mapping requirement.
National manifest: country ISO 3166-1 alpha2, authority, dataset version, schema major/minor, build ID, source URLs/dates/hashes/license terms, source inclusion/exclusion counts, record counts by type, download/installed bytes uint64, shard filenames/sizes/SHA256, generator version and reproducibility inputs; canonical signed manifest via existing trust infrastructure, authenticated payload hash validation before activation; no path traversal/symlink/duplicate entries. Integrity status distinct from availability, no package considered installed solely by filename. Shard within proven file offset limits; builder host only. International packages same normalized structure, never assume FCC-specific enumerations are universal. Research deliver exact layout proposal and independent fixtures; coordinator approves before format freeze.

## Experimental split index requirements
Keep point authorizations (low=high) and nonzero-width inclusive intervals in distinct sections; do not expand blocks. Stable ID namespace and ordering must be specified, including cross-section/country pagination and duplicate policy. Directory entries must cover duplicate-frequency runs spanning pages; page/shard boundaries cannot drop results. Tree summaries must be verified against actual descendant records (minimum start and maximum end, exact leaf span and child relationships); validate discrete sort, type and uniqueness, references, counts, overflow and geometry before activation. Check every source and package generation; a valid signature alone does not imply semantic consistency. Require bounded incremental validation and durable verified-generation state. Research v1 FCCIDX01 remains correctness reference; v2 FCCFRQ02 is an unsigned experimental shard, not an approved package or ABI. Explicit section alignment, page/cache layout and candidate/detail separation still need proposal and independent fixtures.
