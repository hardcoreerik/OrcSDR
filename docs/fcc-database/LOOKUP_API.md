# Lookup API — v0.1 semantics
Native C++17 portable core namespace orcsdr::fcc; no M5GFX, radio, OS dependency. Coordinator gate header defines the first lifecycle key and UI outcome vocabulary; research owns the portable reader and proposes concrete query/result types for review. Frequency exact, tolerance (saturating arithmetic), overlap range, callsign, authority-scoped license ID, organization normalized search, country (optional/all installed), radius/bounding box, service, emission, class, status, AND combined filters; document exact/prefix behavior and deterministic pagination. 64-bit Hz, E7 optional receiver position; no coordinates still supports non-geographic search; radius filter unknown geometry explicitly excluded/marked, not silently distance zero. Cross-border query across installed packages; report missing coverage and partial results independently. Stable result identities and provenance, explicit truncation and bounded max results (initial target 16 per page). No calibrated probability claims.
Async adapter: UI owns bounded request queue submission, worker performs blocking SD reads only; try-submit returns accepted/busy/unavailable, no indefinite waits. Poll publishes value-owned bounded result page, no dangling pointers; cancellation best effort plus mandatory stale-result rejection by request identity, observation identity, package generation, location generation. Closing/reset invalidates current ticket; never match by list index or frequency alone. Separate availability (missing/corrupt/unsupported/stale/available) from lookup outcomes (pending/no_match/candidates/partial/cancelled/error). Cache key includes all query fields and generation; no observed identity inference. Install/remove invalidates generation safely; pin in-flight read handle until release. Candidate association is not transmitter identification. Request/result concrete payload and worker implementation pending research review.

## Performance integration clarification
Exact membership is only a discrete-index optimization, not a complete lookup. Range and tolerance must query both sections. Separate lightweight candidate references from detail hydration, pin country/authority/package generation and stable authorization ID; an old detail request cannot be resolved from a replacement generation. Coalesce identical pending query keys only across identical immutable package set, all filters, location and query semantics; distinct subscriber tickets retain independent cancellation; cancel work only when no subscribers remain. Bounded queue, fairness and per-step record/byte/time budgets; expose partial/incomplete/error, not a false no-match. Stable ordering and pagination across both sections/countries must be specified and tested; a first page is not a complete result set. No storage on DSP/USB/audio/UI callbacks.
