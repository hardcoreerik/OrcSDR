# WebUI v2 Implementation Plan

> Execute inline with superpowers:executing-plans; each task retains its own tests and evidence.

**Goal:** Robust LAN control and independent continuous browser audio without degradation of the Tab5 radio experience.
**Architecture:** Reuse conditioned PCM, native HTTP/WebSocket and Web Audio. Bound all queues and keep networking outside producers.
**Tech Stack:** C++17 / ESP-IDF 5.5.4, vanilla JavaScript/CSS/Canvas, existing host test tools.
**Spec:** `docs/superpowers/specs/2026-09-16-webui-v2.md`.

## Global constraints

No original-checkout edits, driver/startup changes, push, merge, tag, release,
issue closure, or silent sample-rate reduction. Allocation-free bounded PCM
publication. Preserve squelch/encryption, DMA/PSRAM and Wi-Fi pause policy.
Hardware acceptance remains mandatory and separate from automated tests.

## Self-review

All approved areas map to tasks above. No hardware pass is assumed. The exact
network-task implementation must be checked against installed IDF source before
use: asynchronous API naming alone is not a nonblocking guarantee. Local
commits follow passing checks; no full test/build loops until focused tests pass.
