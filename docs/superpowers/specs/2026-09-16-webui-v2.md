## Source findings

`queue_audio_samples` receives conditioned 48 kHz mono from analog demodulation,
P25 voice, and channelizer audio. It currently fills speaker-owned blocks;
`flush_audio_play_batch` taps web audio only after local enable, speaker startup,
and writable-block checks. Analog demand and P25 voice processing also depend
on local mute. Fix all gates, not just the tap. Keep squelch/encryption policy.

The web tap takes every third sample without a dedicated antialias filter.
The 16 kHz ring has 16,384 samples and one consuming cursor shared by clients.
HTTP serves 1,600--4,800-sample finite WAVs, waiting up to approximately 320 ms
inside the handler. Reads discard backlog above the requested clip length.
The page repeatedly replaces its audio source without a continuous timeline.
These are source findings, not measured dropout or throughput results.

## Audio design

Publish conditioned PCM before local speaker buffers. Local enable/volume
control only the speaker. Demodulation demand includes an active remote
subscription and recording, retaining all mode, encryption and squelch gates.
One currently selected PCM producer owns the stream; mode/session changes
advance its generation. Never mix producers during a handoff.

Use native ESP-IDF WebSocket support: 48 kHz signed little-endian 16-bit mono,
20 ms packets (960 samples). Payload is 96 kB/s per listener. No codec or
resampler. Two admitted listeners maximum, independent cursors, one shared
32,768-sample PSRAM ring (65,536 bytes). New listeners start at the live edge.
Retune/reset invalidates old PCM. Reads report dropped samples and generation
changes. Producer work is bounded and allocation-free; it never waits for
network progress. Synchronize bounded copies, use a non-waiting producer
acquisition, and count any contention loss rather than risking a data race.

Wire header: magic/version, stream generation, first sample position, sample
rate, sample count and flags, explicitly encoded little-endian (no packed C++
struct casts). Validate length, format, counts and sequence before playback.
Fixed network staging, at most one pending send per listener. Preserve buffer
lifetime until completion. Close stalled listeners; prevent stale callbacks
from acting on reused sockets. Teardown drains/cancels owned work before state
release. A slow listener must not stall DSP, controls, or another listener.

Browser: scheduled Web Audio buffers on plain HTTP, explicit user activation,
300 ms target and 600 ms maximum INCLUDING scheduled audio. No AudioWorklet
requirement: normal HTTP LAN pages are not secure contexts. Underflow fades to
silence and refills; overflow cancels stale backlog and resynchronizes. Small
bounded playback-rate correction compensates sustained clock drift. Sequence
gaps and new generations reset the timeline. OFF cancels scheduled nodes,
pending retries and that subscription only. Reconnect uses capped backoff.
Do not claim LIVE until playback is running with current PCM. Distinguish
squelch, encrypted/no decoded audio, buffering and network failure.

## Telemetry, controls and presentation

Keep HTTP control/status routes with bounded, validated requests. No silent
command replacement or successful response for rejected input. Validate origin
for browser state-changing/stream requests; retain opt-in trusted-LAN scope,
no implication of authentication or Internet safety. Do not expose credentials.

Name local speaker state explicitly. Browser playback state is browser-owned.
Publish actual remote subscriptions, availability/reason, stream counters,
snapshot age/sequence and spectrum frame identity. Match spectrum frequency,
span and bins in a single coherent frame. Invalidate mode-specific metadata.
No hardcoded V4 identity, fabricated SNR/station data, or missing-Hz rounding.

Lean offline HTML/CSS/JavaScript with separately testable audio logic, embedded
by CMake, no framework/CDN. Dark instrument layout: OrcSDR/mode/connection/UTC,
dominant exact frequency and real identity, large spectrum and waterfall,
compact radio/network/listening telemetry. LISTEN HERE has OFF, BUFFERING,
LIVE, RECONNECTING and ERROR states. Separate Tab5 speaker controls in details.
Use explicit focus, accessible controls and usable D-pad/keyboard navigation.
Support tablet, 1280x720, 1920x1080, 2560x1440 and 3840x2160.

Keep 64 actual bins initially; interpolate only presentation, not RF detail.
Only new spectrum frames append waterfall rows. Freeze/dim stale data with age.
No animated center-frequency mismatch. Bound Canvas backing size/work on 4K.
Benchmark higher telemetry cadence before enabling it; do not raise FFT cost.
Polling has one outstanding request, a timeout and automatic reconnect.

## Resource and acceptance gates

Preserve Hosted 3.0.6 / 10 MHz SDIO, USB PSRAM buffers, internal DMA reserves,
HTTP/mDNS PSRAM policy and intentional radio pause around Wi-Fi operations.
Do not reduce radio sample rate to hide a regression. Instrument baseline and
candidate production/sent rates, occupancy, drops, pending sends, reconnects,
browser depth/underruns, heap/largest DMA block, USB/DSP/local-audio faults,
UI responsiveness and end-to-end audio delay where measurable. Aggregate
diagnostics outside hot paths. Buffered duration alone is not output latency.

Test demand combinations, ring wrap/overflow, independent clients, handoff,
malformed frames/actions, stalled peers, clock drift, reconnect/OFF races,
autoplay rejection, stale metadata and responsive layouts. Use existing host,
UI, documentation and native-IDF checks, plus focused new WebUI tests.

Final hardware runs: V4 FM with suitable dipole, >=10 minutes at 0.960 MSPS
and separately current 2.4 MSPS, representative ~100 ms network conditions,
desktop and actual Android TV WebView. Record exact antenna, frequency,
gain, firmware/hash, WebView version, memory, faults, queues and interruptions.
Repeat independent mute/unmute/volume and two-listener tests; V3C regression,
mode changes and Wi-Fi recovery. User confirms physical audio/UI separately.
Keep evidence for P25 encryption and other decoder non-regression. No issue
closure until accepted, and never close automatically.
