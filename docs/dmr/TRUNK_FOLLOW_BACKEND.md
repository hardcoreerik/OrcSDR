# Tier III group voice trunk-following backend (T3-0)

Independent receive-only fixed-memory parser, site-local map and single-receiver follower. No UI/radio/USB/audio owner. Supported: standard FID 0 TV_GRANT (0x31), logical CSBK and exactly two-block absolute MBC, independent CRC gates, same-slot adjacent 288-dibit cadence, epoch/frequency/CC isolation. Absolute frequencies are MS RX (repeater downlink), in 125 Hz steps; TX field is informational only. No auto-follow from an unresolved logical channel. Site map learns physical channel mapping from qualified absolute grants, not channel-number arithmetic. Conflicts quarantine until explicit site reset. No claim of voice privacy from a grant: downstream qualified clear LC/voice is required. Current scope is group voice only; private/broadcast/data grants, control move, system identity and channel announcement parsing are not implemented. No network-wide automatic discovery or trunked device acceptance yet.

## Standards basis
ETSI TS 102 361-4 V1.11.1 sections 7.1.1.1.1.2, 7.1.1.1.2, 7.2.19.7.1, Annex C.1.1.4; ETSI TS 102 361-1 V2.6.1 sections 7.4, 7.4.1, B.3.8, B.3.12. Header CRC mask AAAA, CSBK A5A5, one final continuation CRC unmasked. No competitor source copied.

## Real-air evidence
Local offline extraction from existing CU8 corpus using previously committed V2 replay DSP (not production frontend): four complete same-slot grant pairs at 152.1575 MHz, five at 152.685 MHz, none at 153.068 MHz or the control-only negative. First pair hex 3100fffc5bbbed3ea71b4bbb / b10d002b49e9a61304ec34c7: target 6011885, source 4106011, TS2, absolute LPCN 173, receive 152157500 Hz, CC13. Second site LPCN 215, advertised receive 152682500 Hz (capture label 152685000 Hz, +2500 Hz difference), CC8, source 4106019, TS2. First site's grants are exactly same-carrier; second site advertises a near-carrier frequency, which must not be silently rounded to the capture label. Cross-carrier tune/return tested synthetically only. No new raw IQ/audio is committed.

## Host testing
From repo root: cmake -S tests/dmr_trunk -B build/trunk -DCMAKE_BUILD_TYPE=Release; cmake --build build/trunk; ctest --test-dir build/trunk --output-on-failure. For sanitizers add -DCMAKE_CXX_FLAGS="-fsanitize=address,undefined -fno-omit-frame-pointer" -DCMAKE_EXE_LINKER_FLAGS="-fsanitize=address,undefined". Keep log in run directory.

## Claude integration
This branch adds a bounded D1 post-BPTC payload tap for types 3,4,5 and D1Adapter. MBC continuation stays FEC-only at D1; the parser checks the complete pair. Preserve this change when merging concurrent D1 voice work. Existing fuzzy-sync rules unchanged for MBC (exact only). Feed Parser every BS burst event, including failure/non-MBC for invalidation, with validated CACH slot, burst_start_dibit, radio epoch, actual tuned channel and monotonic timestamp. Parser output is a grant, NOT call identity, audio, or proof of TSCC. Use only a user-selected/qualified control carrier, one site context; do not feed grants from payload channels into the control monitor. Feed Follower on application owner; SCAN and Follower mutually exclusive tune authorities. Action tune means call existing dv_radio::tune_channel once; mute/flush prior to any retune, wait for accepted owner tune and actual new epoch, then acknowledge matching token. Expected epoch change is part of tune acknowledgement, not unexpected discontinuity. On same carrier select slot without retune. Stop action releases follow mode through existing owner, not direct hardware. Poll tick regularly. Only allow vocoder playback after independent clear voice identity matches; grant itself never authorizes sound. Replay actions must not touch hardware; replay uses isolated follower and map. Preserve timestamps and flush all queues on gap/retune; no dynamic allocation. Audio, UI, automatic site discovery and native IQ end-to-end qualification remain integration work. Add SCAN mode, LIVE small panel, SYSTEMS map in current six-page M5GFX UI, not new dashboard.

Native replay uses the production channelizer and D1 integration receiver. Its test requires at least one validated positive grant and zero grants on the other four recordings, with matching absolute fields. It does not exercise the Tab5 tune/audio path. The adapter header is consumed only by targets already depending on the DMR D1 bridge; add those include/dependency paths during app integration.
