## Implemented frequency shard
All numeric fields little endian, no struct dumps, offsets from file start. 1 GiB maximum per shard; no compression. Header 64 bytes: magic ASCII FCCFRQ02 at 0 (8), major u16=2 at 8, minor u16=0 at 10, header bytes u32=64 at 12, uppercase country ASCII 2 at 16, zero 6 at 18, exact count u64 at 24, interval count u64 at 32, node count u64 at 40, interval offset u64 at 48, node offset u64 at 56. Exact table starts 64, interval offset=64+24*exact count, node offset=interval offset+24*interval count. End=node offset+32*node count, exact file size required. Each entry 24 bytes: low u64 at 0, high u64 at 8, nonzero authorization row ID u64 at 16. Exact low=high; ranges low<high. Sort each by (low,high,id). National ID unique within this prototype's single shard. Production IDs below. Tree uses 32 intervals per leaf; number of leaves is next power of two >= ceil(interval count/32), zero if no intervals. Node count=2*leaves-1 if nonzero. Node 32 bytes: min low u64 at 0, max high u64 at 8, first interval ordinal u64 at 16, count u64 at 24. Root at 0; internal node i children 2i+1,2i+2; first/count zero for internal. Nonempty leaf i starts at (i-(leaves-1))*32, count min(32, remaining). Empty leaf (MAX,0,0,0). Internal envelope = min(child lows), max(child highs). DFS left-first. Binary search exact table lower bound then scan within high; range DFS prunes non-overlapping envelope and tests each leaf interval inclusively. Output exact before ranges; deterministic within table, not ranked. No arbitrary per-frequency expansion. C++ reader caps each step reads and result count, fixed cursor stack. Host builder SQLite disk-backed sorts unsigned integers via big-endian keys; packed bytes are little endian. Header arithmetic checked; semantic index validation NOT yet implemented in C++. Immutable authenticated and semantically checked storage is a precondition, not supplied by current prototype. Mutable cursor is trusted experimental state, not a serialized ticket. No global pagination across shards yet.

## Proposed metadata shard (not implemented)
Header 80 bytes: magic ASCII FCCMET02 at 0, u16 major 2 at 8, u16 minor 0 at 10, u32 header size 80 at 12, ASCII country at 16, zero 6 at 18, 32-byte package identity SHA256 at 24 (hash of canonical build inputs, not manifest/payload), u32 section count at 56 (max 64), u32 shard number at 60, u64 directory offset=80 at 64, u64 total file length at 72. Directory entry 32 bytes: u32 type at 0, u32 flags at 4 (bit0 required; other bits zero), u64 offset at 8, u64 byte length at 16, u32 count at 24, u32 stride at 28. Sorted by type, no duplicate types, nonoverlap, 8-byte section alignment, zero padding; fixed length=count*stride, variable byte section stride=1/count=length. Check all offsets, lengths, alignment, arithmetic and size before read. Shard <=1 GiB. Exact 2.0 only until minor rules approved. Unknown optional sections may be skipped only if flags valid and all bounds checked; unknown required or incompatible version rejected. No compression initially.
All row fields below listed in sequential order starting offset zero; u64=8 bytes, u32/i32=4, u16=2. No implicit padding. Row references u64 = (shard number <<32)|(1-based row ordinal), zero missing, scoped to section type and country/package. Shard number 0 allowed; row ordinal 0 invalid except missing. Strings use same shard encoding but low32 is byte offset +1 into type 1; zero missing, empty valid length zero. Stable cross-version identity is exact tuple (country, authority, source system, entity type, source key) held as string references, never package ordinal. A changed package ordinal cannot be used as historical identity. Deduplicate exact UTF-8 bytes, strict decoding, length limit 4096 bytes, no embedded NUL, never cut original values; oversize explicit coverage exclusion pending alternate blob policy. Type 1 string blob record u32 length then bytes, no per-string padding. Order lexicographic unsigned bytes; verify reference points to actual entry boundary. Search key NFC + Unicode casefold + NFC + trim/collapse ASCII whitespace; pin Unicode version in build inputs, embedded query must match exact normalization or report unsupported. Preserve originals.
Sections:
1 strings, stride 1.
2 source, stride 80: authority u64 string, system u64 string, URL u64 string, snapshot version u64 string, published date i32 (days since 1970, INT32_MIN unknown), terms u64 string, flags u32 (bit0 date known; remainder zero), archive SHA256 32 bytes, in that sequence (8*4+4+8+4+32=80). Hash all-zero forbidden for actual snapshot.
3 provenance, stride 32: source ref u64, original key string u64, member name string u64, row ordinal u64 (0 unknown).
4 license, stride 64: provenance u64, authority scoped license identifier string u64, callsign string u64, service raw string u64, status raw string u64, grant/expiry/effective/cancel i32 each, normalized status u16 (0 unknown,1 active,2 expired,3 cancelled,4 terminated,5 other), reserved zero u16/u32. Source key preserved via provenance.
5 party, stride 24: provenance u64, licensee name string u64, normalized organization key string u64. Mailing address is excluded from this initial device proposal, never treated as location.
6 authorization, stride 80: provenance u64, license ref u64, low Hz u64, high Hz u64, original frequency text string u64, original upper text string u64, original unit string u64, station class raw string u64, role u16 (0 unknown,1 TX,2 RX,3 allocation), flags u16 (bit0 frequency present; bit1 sub-Hz exact value rounded outward for candidate retrieval, never identity), status raw string u64, reserved u32=0. If frequency absent both endpoints zero, flag clear, no frequency index entry.
7 site, stride 48: provenance u64, name string u64, geometry ref u64, latitude i32 E7, longitude i32 E7, accuracy metres u32 (MAX unknown), datum/source string u64, flags u32 (bit0 coordinate present; bit1 actual transmitter, bit2 receiver, bit3 administrative excluded from geo; other bits zero). Missing coordinates both zero with bit0 clear; valid zero coordinate bit0 set; only actual transmitter eligible as point TX.
8 antenna, stride 24: provenance u64, site ref u64, name/number string u64.
9 emission, stride 24: provenance u64, raw designator string u64, normalized designator string u64. Classification computed separately, never confirmed protocol.
10 geometry, stride 48: provenance u64, geometry type u16 (0 unknown,1 point,2 polygon,3 multipolygon,4 nationwide,5 other geographic area), flags u16 (bit0 antimeridian crossing, bit1 bbox present), south/west/north/east i32 E7, first ring ref u64, ring count u32, source area code string u64. Zero ring ref/count for nonpolygon. Bounding boxes crossing 180 represented west>east, normalize longitude to [-180,180), poles included. Missing geometry not zero-radius point.
11 rings, stride 24: polygon ordinal u32 (0-based within geometry), role u16 (1 exterior,2 hole), reserved u16 zero, first vertex ref u64, vertex count u32, reserved u32 zero. Rings contiguous within shard, vertex count>=4 closed explicitly, first and last equal, no invalid/self-intersecting rings; geodesic interpretation and polygon validation still require coordinator review.
12 vertices, stride 8: lat E7 i32, lon E7 i32.
13 links, stride 32: provenance ref u64, from ref u64, to ref u64, from type u16, to type u16, relation u16 (1 license-party,2 authorization-site,3 authorization-antenna,4 authorization-emission,5 authorization-geometry,6 TX-to-RX path,7 license-authorization,8 source-duplicate-of), reserved u16 zero. Preserve distinct endpoints and evidence; conflicting records stay separate. Sorted (from type,from,relation,to type,to,provenance).
14 search postings, stride 32: kind u16 (1 callsign,2 license ID,3 organization,4 service,5 emission,6 class,7 status), entity type u16, reserved u32 zero, normalized key string u64, target entity ref u64, authority string u64 (required for license ID, zero otherwise). Sort (kind,key UTF-8 bytes,authority UTF-8 bytes,target type,target ID). Binary search with paged string comparisons; no substring promise; exact/prefix only. License-only results for records without assigned frequency. Dedup union by canonical identity at result level.
15 geo postings, stride 24: cell ID u32, type u16 (7 site or 10 geometry), flags u16 zero, target ref u64, authorization ref u64 (0 if none). Grid cell ID=(floor((lat+90)*4) clamped to 719)*1440 + floor((lon+180)*4); coordinates degrees; integer E7 arithmetic. Sort cell, target type/ref, authorization. Points one cell; area bounding covers all intersected cells except large/nationwide geometry, which uses special cell MAX. To avoid explosion, >256 intersected cells use MAX. Query includes MAX postings and actual geometry test; unknown geometry explicitly excluded in strict spatial filter and counted. Cell index proposed; performance and precise polygon semantics not qualified.
All section types mandatory for complete metadata, even empty. Referential integrity, ordered keys, canonical source relationships, semantic geometry validation and coverage counts required before activation. Proposed IDs and string references must be checked before dereference. Frequency index production row ID is authorization ref type 6; each shard disjoint authorization IDs; manifest lists per-shard frequency bounds, never drops long spans. Multi-shard merge deterministic by (country,shard,exact-before-range,low,high,id); no silent omissions. Frequency shard currently lacks package ID; proposal binds it by authenticated manifest hash; coordinator may require embedded identity. Do not call this production-ready.

## Manifest and normalized staging
Host normalized schema mirrors source/provenance/license/party/authorization/site/antenna/emission/geometry/ring/vertex/link tables. Natural keys scoped by country/authority/source/entity/key. Foreign keys enforced; identical records may deduplicate only if full typed payload and provenance can be retained, conflicting versions not collapsed. Snapshot time separate from effective/status dates. Source absence and unsupported records explicit; raw files not committed. Manifest canonicalization/signature delegated to existing trust infrastructure; propose UTF-8 canonical JSON sorted keys, no floats, exact uint64 represented decimal strings, SHA256 hex lowercase, arrays sorted by named stable keys; final signing/canonical policy requires coordinator approval. Required fields: country, authority list, dataset version, schema major/minor, package identity, generator commit, source URLs/date/hash/terms, original/extracted counts and bytes, included/excluded counts by reason/table, package files with names/bytes/hash/shard/range bounds, download and installed size. Signed manifest binds all payload bytes before activation; no archive traversal/duplicates/symlinks. No current signing code or national data.
